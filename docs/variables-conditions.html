Variables & Conditions

Two independent, small systems: variables interpolate live text, conditions gate visibility and interactivity.

Variables

Any rendered text — a Text element's content, a button's label or tooltip, a menu's title, an input's label — is scanned for {{ key }} tokens and interpolated per-player at render time.

<text>Welcome, {{ player.name }}! Online: {{ server.online }}</text>

Built-in variables

KeyResolves to
player.namePlayer's name
player.uuidPlayer's UUID
player.levelExperience level
player.healthHealth, formatted to 1 decimal
player.foodFood level
player.worldWorld name
player.gamemodeGame mode name
player.x / player.y / player.zBlock coordinates
player.pingPlayer's ping
server.onlineOnline player count
server.max_playersMax player count
server.nameServer name
server.versionServer version string
server.tpsCurrent TPS, formatted to 2 decimals

Registering your own

HTMLib.variables().register("shop.coins", player -> String.valueOf(economy.balance(player)));

A VariableResolver is just String resolve(Player player). Notes on resolution:

  • An unregistered key renders literally, e.g. {{ nope }} stays as-is.
  • If a resolver throws, the token resolves to an empty string rather than breaking the menu.
  • You can register a catch-all with VariableRegistry.fallback(Function<String, VariableResolver>), useful for namespaced/dynamic keys.

PlaceholderAPI

If PlaceholderAPI is installed, HTMLib runs its own {{ }} interpolation first and then passes the result through PlaceholderAPI, so %placeholder% tokens from any PlaceholderAPI expansion work in the same text without extra wiring:

<text>Balance: %vault_eco_balance%</text>

Conditions

Condition is a functional interface: boolean test(ConditionContext context). ConditionContext wraps the Player plus any attributes you choose to attach.

Where conditions apply

JavaMarkupEffect
component.visibleIf(condition)visible-if="..."Hides the element (and its children, if a container) when false.
button.enabledIf(condition)enabled-if="..."Keeps the button visible but rejects clicks when false.
component.permission(node)permission="..."Shorthand for visibleIf(Condition.permission(node)).

Combining conditions in Java

Condition canBuy = Condition.permission("myplugin.shop")
    .and(ctx -> economy.balance(ctx.player()) >= 50)
    .negate();

Condition always = Condition.always();
Condition never = Condition.never();
Condition notAdmin = Condition.not(Condition.permission("myplugin.admin"));

Condition expressions (markup / strings)

ConditionRegistry.parse(String) turns a short string into a Condition — this is what powers visible-if and enabled-if in markup:

SyntaxMeaning
permission:some.node or perm:some.nodeTrue if the player has that permission.
some.node (no prefix)Same as permission:some.node — a bare string is treated as a permission node.
!permission:some.nodeLeading ! negates the whole expression.

Registering a custom prefix

Register your own prefix to unlock expressions like economy:100 in markup:

HTMLib.conditions().register("economy", remainder -> {
    double required = Double.parseDouble(remainder);
    return ctx -> economy.balance(ctx.player()) >= required;
});
<button action="myplugin:buy.shield" enabled-if="economy:80">Buy Shield</button>

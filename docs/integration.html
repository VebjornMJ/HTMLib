For Plugin Developers

HTMLib is installed as its own plugin. Your plugin depends on it at compile time and runtime, the same way you'd depend on any other API-providing plugin like Vault or PlaceholderAPI.

Gradle dependency

HTMLib is split into small modules, all under group dev.htmlib. The htmlib-paper jar you install on the server already bundles htmlib-api, htmlib-layout, htmlib-events, htmlib-navigation and htmlib-markup at runtime, so your own build only needs them as compileOnly:

dependencies {
    compileOnly("dev.htmlib:htmlib-api:0.1.0")
    compileOnly("dev.htmlib:htmlib-events:0.1.0")
    compileOnly("dev.htmlib:htmlib-markup:0.1.0")   // only if you parse XML markup yourself
}

The API surface you'll actually import lives in a handful of packages:

PackageContains
dev.htmlib.api.componentMenu, Button, Row, Column, Div, Text, Icon, Image, Input, ListComponent
dev.htmlib.api.conditionCondition, ConditionContext, ConditionRegistry
dev.htmlib.api.navigationMenuController, MenuRenderer
dev.htmlib.api.variableVariableRegistry, VariableResolver
dev.htmlib.eventsAction, ActionEvent, ActionRegistry, EventBus and the menu lifecycle events
dev.htmlib.markupMarkupLoader, CssParser, MarkupException

plugin.yml

Declare HTMLib as a dependency so your plugin loads after it (use softdepend instead if your plugin can also run without HTMLib installed):

name: MyPlugin
main: com.example.myplugin.MyPlugin
version: 1.0.0
api-version: "26.2"
depend: [HTMLib]

Talking to HTMLib at runtime

Once HTMLib is enabled, dev.htmlib.paper.HTMLib is the static facade you'll use from your own plugin code — it forwards to HTMLib's live registries:

import dev.htmlib.paper.HTMLib;

HTMLib.menus().register(menu);              // MenuRegistry
HTMLib.registerAction("myplugin:buy", ev -> ...); // shorthand for HTMLib.actions().register(...)
HTMLib.actions();                            // ActionRegistry
HTMLib.variables();                          // VariableRegistry
HTMLib.conditions();                         // ConditionRegistry
HTMLib.events();                             // EventBus

HTMLib.open(player, "myplugin:shop");        // open a registered menu by id
HTMLib.open(player, menu);                   // open a Menu instance directly
HTMLib.back(player);
HTMLib.close(player);

Calling any of these before HTMLib has finished enabling (for example too early in your own onEnable, if it doesn't depend on HTMLib) throws IllegalStateException("HTMLib is not enabled yet") — another reason to declare the dependency in plugin.yml rather than relying on load order.

Menu.show(player)

As a shortcut, any Menu instance can open itself without going through the facade:

menu.show(player);

This calls into HTMLibRuntime, the low-level binding the paper module installs on enable and clears on disable. You generally won't touch HTMLibRuntime directly — HTMLib and Menu.show(player) cover normal usage.

Note: a menu only needs to be registered (HTMLib.menus().register(menu)) if you want to open it by id — via action="open:<id>", HTMLib.open(player, "id"), or /htmlib open. Opening a Menu instance directly with menu.show(player) or HTMLib.open(player, menu) works either way.
